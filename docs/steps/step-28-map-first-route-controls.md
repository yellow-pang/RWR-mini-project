## 1. 작업 목표

홈 화면을 지도 중심 구조로 재배치하고, 코스 생성 조건을 더 쉽게 조작할 수 있도록 운동 유형별 거리 프리셋, 출발지/도착지 바꾸기, 우회 강도 선택을 추가했다.

이번 Step의 핵심 기준은 아래와 같다.

- 모바일: 지도 중심 + 하단 고정 조건 패널
- 데스크톱: 왼쪽 조건 패널 + 오른쪽 지도
- 거리 기준에서 운동 유형별 거리 프리셋 제공
- 출발-도착 코스에서 출발지/도착지 바꾸기 제공
- 출발-도착 코스에서 `가볍게 / 적당히 / 많이` 우회 강도 선택
- `detourLevel` 요청값을 서버 경유지 생성 로직에 반영
- POI 기반 경유지는 후속 Step으로 분리

## 3. 중요 변경 내용

### 3.1 지도 중심 홈 레이아웃

홈 화면에 지도 영역을 추가했다. 출발지가 선택되면 해당 위치를 지도 기준으로 표시하고, 이전 추천 결과가 있으면 생성 경로 좌표도 지도에 표시할 수 있게 했다.

모바일에서는 조건 영역을 화면 아래 고정 패널처럼 보이게 구성했다. 드래그 가능한 실제 바텀시트는 아니며, 1차 구현에서는 하단 패널과 내부 스크롤로 처리한다.

데스크톱에서는 좌측 조건 패널과 우측 지도 영역이 나란히 보이도록 레이아웃을 확장했다.

### 3.2 운동 유형별 거리 프리셋

거리 기준 추천에서 운동 유형에 따라 다른 거리 프리셋을 사용한다.

| 운동 유형 | 거리 프리셋              |
| --------- | ------------------------ |
| 걷기      | 1km, 2km, 3km, 직접 설정 |
| 조깅      | 2km, 3km, 5km, 직접 설정 |
| 러닝      | 3km, 5km, 7km, 직접 설정 |

운동 유형을 바꿨을 때 현재 거리값이 새 프리셋에 없으면 첫 번째 프리셋으로 보정한다. 직접 설정은 기존 슬라이더 범위 `0.5km ~ 10km`를 유지한다.

### 3.3 출발지/도착지 바꾸기

출발-도착 코스의 도착지 영역에 `출발/도착 바꾸기` 버튼을 추가했다. 버튼을 누르면 기존 `routeLocation`과 `destinationLocation` 상태를 교환한다.

현재 위치 사용은 기존 정책대로 출발지 보조 기능으로만 유지한다.

### 3.4 우회 강도 선택

출발-도착 코스에서만 우회 강도 선택 UI를 표시한다.

| 표시   | 내부 값  | 서버 반영                                  |
| ------ | -------- | ------------------------------------------ |
| 가볍게 | `light`  | 경유지 수와 offset을 줄임                  |
| 적당히 | `medium` | 기존 기준 유지                             |
| 많이   | `strong` | 목표 거리 안에서 경유지 수와 offset을 늘림 |

선택값은 `POST /api/routes/address-point-to-point` 요청 body의 `detourLevel`로 전달한다.

### 3.5 서버 경유지 생성 반영

서버는 `detourLevel`을 검증하고, 출발-도착 랜덤 경유지 생성 시 경유지 수와 수직 offset에 반영한다.

단, 최종 추천 여부는 기존 Step 27의 목표 거리 허용 범위 검증이 우선이다. `strong`을 선택해도 실제 ORS 경로가 목표 거리 범위를 벗어나면 추천 후보에서 제외된다.

## 5. 변경하지 않은 항목

| ------------------------- | --------- | ---------------------------------------------------- |
| DB 스키마                 | 변경 없음 | `detourLevel`은 요청 단위 값이며 저장하지 않음       |

| npm 패키지                | 추가 없음 | 기존 React/CSS/Express 구조로 구현                   |
| POI 경유지                | 변경 없음 | 외부 API와 fallback 정책이 필요해 후속 Step으로 분리 |

## 7. 남은 확인 사항

- 실제 모바일 브라우저 375px에서 하단 조건 패널의 높이와 스크롤 체감 확인
- 실제 ORS API 환경에서 `strong` 우회 강도 선택 시 후보 실패율과 응답 시간 확인
- 출발지만 있거나 도착지만 있는 상태에서 출발/도착 바꾸기 UX가 사용자의 기대와 맞는지 확인
- POI 기반 경유지 후보는 후속 Step에서 카카오 키워드 검색 등 외부 API 정책과 함께 검토
