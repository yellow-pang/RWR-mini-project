## 1. 작업 목표

주소 기반 ORS 생성형 코스가 지도 위에서 일부 겹쳐 보일 때 사용자가 진행 방향을 더 쉽게 이해할 수 있도록 경로 위 방향 화살표를 추가했다.

이번 작업은 프론트엔드 지도 표현 보완만 포함한다. 서버 API, DB 스키마, Docker 설정, 환경변수, 외부 API 키는 변경하지 않았다.

---

## 2. 문제 상황

Step 21 이후 RWR의 메인 흐름은 사용자가 선택한 주소와 운동 조건을 기준으로 ORS 순환 코스를 생성하는 방식이다. ORS가 실제 도로망을 따라 경로를 만들기 때문에, 짧은 구간에서는 같은 길을 다시 지나거나 매우 가까운 길을 왕복처럼 지나는 결과가 나올 수 있다.

기존 지도 표시는 초록색 단일 폴리라인만 사용했다. 이 방식은 코스의 전체 모양은 보여주지만, 선이 겹치거나 맞닿는 구간에서는 사용자가 아래 내용을 바로 알기 어렵다.

- 어느 쪽으로 출발해서 어느 방향으로 도는지
- 겹쳐 보이는 구간이 실제로는 왕복인지, 단순히 가까운 길인지
- 상세 화면에서 따라가야 하는 경로의 흐름이 무엇인지

그래서 이번 Step에서는 경로 선 자체를 바꾸기보다, 기존 선 위에 진행 방향을 나타내는 화살표를 얹는 방식으로 보완했다.

## 4. 중요 변경 내용

### 4.1 카카오맵 경로 방향 화살표 추가

`MapView`에서 `routeCoordinates`가 있는 경우 전체 경로 길이를 기준으로 중간 지점을 샘플링하고, 각 지점의 진행 각도를 계산해 방향 화살표를 표시한다.

표시 개수는 화면 크기와 지도 용도에 맞춰 다르게 적용했다.

| 지도 위치      | `compact` 값 | 화살표 개수 | 이유                                                         |
| -------------- | ------------ | ----------- | ------------------------------------------------------------ |
| 결과 카드 지도 | `true`       | 3개         | 카드 안의 작은 지도라 너무 많은 표시를 피함                  |
| 상세 화면 지도 | `false`      | 5개         | 사용자가 경로를 자세히 확인하는 화면이라 방향 힌트를 더 제공 |

화살표는 Kakao `CustomOverlay`로 표시한다. 별도 지도 라이브러리나 npm 패키지는 추가하지 않았다.

### 4.2 경로 좌표 처리 방식

ORS 응답의 경로 좌표는 GeoJSON 형식인 `[lng, lat]` 순서다. 지도에서 쓰기 위해 각 좌표를 아래 형태로 변환한다.

```js
{
  (lat, lng);
}
```

변환 과정에서 숫자로 바꿀 수 없는 좌표나 비어 있는 좌표는 제외한다. 유효한 좌표가 2개 미만이면 방향 화살표를 만들지 않는다.

### 4.3 방향 화살표 위치 계산

화살표 위치는 단순히 좌표 배열의 몇 번째 점을 고르는 방식이 아니라, 전체 경로 길이를 기준으로 일정한 간격에 가깝게 선택한다.

처리 흐름은 다음과 같다.

1. 인접한 두 좌표 사이의 거리를 계산한다.
2. 모든 구간 거리를 더해 전체 경로 길이를 구한다.
3. 전체 길이를 기준으로 3개 또는 5개의 목표 지점을 고른다.
4. 목표 지점이 포함된 구간을 찾는다.
5. 해당 구간의 시작점과 끝점 사이에서 실제 화살표 위치를 보간한다.
6. 같은 구간의 진행 방향 각도를 계산해 화살표 회전값으로 사용한다.

이렇게 하면 좌표가 촘촘한 구간에 화살표가 몰리는 것을 줄이고, 사용자가 전체 경로 흐름을 더 균형 있게 볼 수 있다.

### 4.4 방향 각도 계산

각 화살표가 어느 방향을 바라볼지는 두 좌표 사이의 방위각으로 계산한다.

예를 들어 한 구간이 북쪽으로 진행하면 화살표는 북쪽 방향을 향하고, 동쪽으로 진행하면 동쪽 방향을 향한다. CSS 화살표 기본 모양이 오른쪽을 향하도록 만들어져 있어서, 계산된 방위각에서 90도를 보정해 화면 회전값으로 사용했다.

### 4.5 SDK fallback 프리뷰 방향 힌트 추가

카카오맵 SDK를 사용할 수 없거나 좌표가 없어 `MapPreview`가 표시되는 경우에도 SVG 예시 경로 위에 방향 화살표를 추가했다.

이 프리뷰의 화살표는 실제 ORS 좌표 기반은 아니다. 다만 fallback 상태에서도 사용자가 "경로는 진행 방향을 가진 선"이라는 점을 같은 방식으로 이해할 수 있도록 예시 경로 위에 방향 힌트를 제공한다.

## 7. 사용자 관점 동작

사용자가 주소 기반 코스를 생성하면 결과 카드 지도에 초록색 경로와 함께 작은 방향 화살표가 표시된다. 이 화살표는 코스를 어느 방향으로 따라가야 하는지 알려준다.

사용자가 상세 화면으로 이동하면 더 큰 지도에 방향 화살표가 더 많이 표시된다. 겹쳐 보이는 선이 있어도 경로의 흐름을 따라가며 이해할 수 있다.

카카오맵 SDK가 로드되지 않아 프리뷰 지도가 표시되는 상황에서도 예시 경로 위에 방향 화살표가 보여서, 지도 표현의 의도는 유지된다.

## 9. 남은 확인 사항

빌드 검증은 통과했지만, 실제 카카오맵 화면에서 아래 항목은 브라우저로 추가 확인하면 좋다.

- 겹치는 ORS 생성형 코스에서 방향 화살표가 충분히 잘 보이는지
- 모바일 375px 화면의 compact 지도에서 화살표가 너무 많아 보이지 않는지
- 상세 화면 지도에서 화살표가 코스명 인포윈도우나 시작점 마커와 어색하게 겹치지 않는지
- 필요하면 후속 Step에서 출발/도착 라벨 또는 시작점 강조 방식을 추가할지
