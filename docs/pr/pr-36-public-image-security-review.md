## 개요

공개 GHCR 이미지는 누구나 내려받아 내부 파일·레이어·빌드 정보를 분석할 수 있으므로 운영 비밀값과 개인 데이터의 포함 여부를 점검했다. 공개 SHA 3개의 web/server amd64·arm64 이미지, 55개 고유 레이어, 공개 빌드 메타데이터와 게시 로그 3건에서 대조한 운영 비밀값과 환경변수 파일·사용자 데이터 덤프가 발견되지 않았다.

서버 root 실행, `COPY . .`의 불필요한 파일 포함, 민감파일 제외 규칙의 부족은 확인했다. 현재는 링크로 구현 경험을 보여주는 포트폴리오 용도라는 사용자 판단에 따라 공개 배포를 유지하고, 즉시 구현 대신 점검 근거·남은 위험·유예 이유·향후 수정과 검증 순서를 기록한다.

## 주요 변경 내용

- 점검 당시 이미지 SHA와 Actions 실행 링크, 검사한 레이어·로그 범위를 기록한다.
- 실제 운영 Secret의 미검출과 root 실행·파일 복사·제외 규칙의 보완 필요를 구분한다.
- Kakao JavaScript 키의 HTML·provenance 공개와 서버 REST 키 분리를 설명한다.
- 공개 유지의 목적과 수정 유예 이유를 기록하고 비root 실행·COPY 축소·제외 규칙·포트·CI 검사 등의 후속 작업을 제시한다.
- 포트폴리오 용도가 무위험 판정은 아니며 실제 서비스 전환이나 Secret 유출 시 판단을 다시 해야 함을 명시한다.

## 검증

- 직전 보안 점검의 임시 결과 보고서와 SHA·이미지 수·레이어 수·로그 수 대조 완료.
- 문서 5개의 UTF-8·상대 링크·비밀값 검사 통과.
- 새 문서의 줄바꿈용 끝 공백을 제거한 뒤 `git diff --cached --check` 통과.
- stage 범위가 문서 5개로 한정되는지 확인 완료.
- 문서 변경만 있으므로 애플리케이션 lint/build·서버 문법 검사는 재실행하지 않았다.

## 후속 확인

- 공개 이미지와 현재 배포 구조를 유지한다.
- Docker·코드·환경변수·DB·GitHub 공개 범위를 변경하지 않는다.
- 사용자 요청에 따라 로컬 문서 커밋까지만 수행한다. push·PR 생성·main 병합·운영 배포는 포함하지 않는다.
- 실제 보완이 필요해지면 Step 36의 수정 위치와 검증 기준으로 별도 계획을 작성한다.
