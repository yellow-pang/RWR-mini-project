## 개요

`docs/images`의 목업을 참고해 앱 화면을 정리하되, 실제 웹/앱 서비스에서 불필요한 스마트폰 프레임 장식은 제거했다.

모바일에서는 앱처럼 전체 화면을 사용하고, PC에서는 중앙 웹앱 컨테이너로 표시되도록 레이아웃을 보정했다. 또한 풀스택/PostgreSQL 기준 코드 작성 규칙에 맞춰 기능 없는 헤더 버튼은 비상호작용 아이콘으로 전환하고, CSS 색상/그림자 값은 변수 중심으로 정리했다.

| 구분 | 내용 |
| --- | --- |
| 레이아웃 | 목업용 상태바, 노치, 홈 인디케이터 제거 |
| 반응형 | 모바일 전체 화면, PC 중앙 웹앱 컨테이너 구성 |
| 홈 화면 | 요구사항 우선으로 조건 선택 전 추천 버튼 비활성 유지 |
| 헤더 아이콘 | 메뉴/알림/필터/삭제 아이콘을 비상호작용 요소로 정리 |

| CSS | 색상/그림자 값을 CSS Custom Properties 중심으로 정리 |
| 문서 | Step 11 계획, PR, 완료 문서 작성 |

## 변경 이유

목업 이미지는 실제 스마트폰에서 보이는 예시였지만, 웹 서비스 화면에 그대로 반영하면 브라우저 안에 또 다른 스마트폰 장치가 들어간 것처럼 보일 수 있다.

RWR은 모바일 브라우저와 PC 브라우저 모두에서 접근 가능한 반응형 웹 서비스이므로, 장치 프레임이 아니라 실제 앱 화면 자체가 반응형으로 보이도록 조정했다.

또한 아직 동작하지 않는 메뉴/알림/필터/삭제 버튼은 사용자가 누를 수 있는 기능으로 오해할 수 있다. 현재 MVP 범위에서는 시각적 자리만 남기고 `button`이 아닌 정적 아이콘으로 표시한다.

## 확인 시나리오

1. 모바일 폭에서 홈 화면이 스마트폰 프레임 없이 전체 앱 화면처럼 표시되는지 확인한다.
2. 조건을 모두 선택하기 전 추천 버튼이 비활성인지 확인한다.
3. 초기화 클릭 시 거리/시간/운동 유형 선택이 모두 해제되는지 확인한다.
4. 메뉴/알림/필터/삭제 아이콘이 버튼처럼 hover/커서 동작을 보이지 않는지 확인한다.
5. 결과/상세 화면의 지도 프리뷰가 특정 장소명으로 고정 표시되지 않는지 확인한다.
