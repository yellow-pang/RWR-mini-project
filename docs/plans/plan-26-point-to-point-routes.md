> **브랜치**: `feat/step-26-point-to-point-routes`

## 1. 작업 배경

현재 RWR의 주소 기반 생성형 코스는 출발 주소 하나를 기준으로 ORS `round_trip` 옵션을 사용해 다시 출발지로 돌아오는 순환 코스를 만든다.

실제 사용자 테스트에서는 순환 코스뿐 아니라, 점심 식사 후 식당에서 회사로 돌아가거나 약속 장소에서 집 근처까지 이동하는 상황처럼 출발지와 목적지가 다른 산책 수요가 확인되었다. 이 경우 사용자는 최단 직선 또는 최단 보행 경로가 아니라, 두 지점 사이 주변을 적당히 둘러보며 걷는 랜덤 코스를 원한다.

Step 26에서는 기존 순환 코스 흐름을 유지하면서, 출발지와 목적지를 따로 입력하는 생성형 코스 모드를 추가한다. 1차 구현은 생성형 ORS 코스를 DB에 저장하지 않는 기존 정책을 유지하고, DB 스키마, Docker 설정, 환경변수, npm 패키지는 변경하지 않는다.

---

## 2. 목표

- 홈 화면에서 사용자가 `순환 코스`와 `출발-도착 코스` 중 하나를 선택할 수 있게 한다.
- `순환 코스` 선택 시 기존처럼 출발 주소 하나로 ORS round trip 경로를 생성한다.
- `출발-도착 코스` 선택 시 출발 주소와 도착 주소를 각각 선택할 수 있게 한다.
- 출발지와 목적지가 모두 좌표로 확정된 경우에만 코스 생성 버튼을 활성화한다.
- 출발-도착 코스의 거리 조건은 출발지부터 도착지까지의 전체 예상 거리로 처리한다.
- 현재 위치 사용 버튼은 출발지 입력 보조에만 제공하고, 도착지는 주소 검색으로 선택한다.
- 서버에 출발-도착 분리 경로 생성 API를 추가한다.
- 서버는 출발지와 목적지 사이에 랜덤 경유지를 만들어 ORS Directions API로 보행 경로를 생성한다.
- ORS 경로 생성 실패 시 저장 DB 코스 fallback은 사용하지 않고, 서버 내부에서 경유지를 바꿔 최대 3회까지 재시도한다.
- 결과 카드와 상세 화면은 기존 생성형 ORS 코스 표시 구조를 최대한 재사용한다.
- 지도에서는 출발/도착 지점을 순환 코스와 다르게 분리해서 보여준다.
- 생성형 출발-도착 코스도 즐겨찾기는 숨기고 공유만 허용하는 기존 생성형 코스 정책을 유지한다.

## 4. 사용자 흐름

### 4.1 순환 코스

1. 사용자가 `순환 코스`를 선택한다.
2. 출발 주소를 선택하거나 현재 위치를 사용한다.
3. 거리, 소요 시간, 운동 유형을 선택한다.
4. `코스 생성`을 누른다.
5. 기존 `POST /api/routes/address-round-trip` 흐름으로 순환 코스를 생성한다.

### 4.2 출발-도착 코스

1. 사용자가 `출발-도착 코스`를 선택한다.
2. 출발 주소를 선택하거나 현재 위치를 출발지로 사용한다.
3. 도착 주소를 선택한다.
4. 거리, 소요 시간, 운동 유형을 선택한다.
5. `코스 생성`을 누른다.
6. 클라이언트가 `POST /api/routes/address-point-to-point`로 출발지/목적지/조건을 전송한다.
7. 서버가 출발지와 목적지 사이에 랜덤 경유지를 만들고 ORS 보행 경로를 생성한다.
8. ORS 생성이 실패하면 서버가 경유지를 바꿔 최대 3회까지 재시도한다.
9. 3회 모두 실패하면 저장 DB 코스 fallback 없이 실패 메시지를 반환한다.
10. 성공하면 결과 화면에 생성형 코스를 표시한다.

## 5. 구현 방향

| 항목             | 결정                                                        | 이유                                                                       |
| ---------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| 추천 모드        | `roundTrip` / `pointToPoint`                                | 기존 흐름을 깨지 않고 새 흐름을 병렬 추가하기 위함                         |
| 주소 선택 UI     | 기존 Kakao 우편번호 선택 레이어 재사용                      | 새 외부 API나 패키지 없이 안정적인 주소 선택 가능                          |
| 현재 위치 버튼   | 순환 코스와 출발지 입력 보조로 사용                         | 목적지는 사용자가 명확히 선택하는 편이 혼동이 적음                         |
| 서버 API         | `/routes/address-point-to-point` 신규 추가                  | 기존 `/address-round-trip` 의미를 유지하고 책임을 분리                     |
| ORS 요청         | `coordinates`에 출발지, 랜덤 경유지, 목적지를 순서대로 전달 | 최단 경로가 아니라 산책형 우회 경로를 만들기 위함                          |
| 랜덤 경유지 개수 | 거리 조건에 따라 1~3개                                      | 1km는 과도한 우회를 피하고, 3/5km는 랜덤성을 높임                          |
| 거리 조건 의미   | 선택 거리를 출발지부터 도착지까지의 전체 예상 거리로 처리   | 사용자가 `3km`를 선택했을 때 총 3km 정도를 기대하는 것이 자연스러움        |
| 목표 거리 처리   | 기본 출발-도착 거리가 선택 거리보다 길면 경유지 최소화      | 선택 거리보다 길어질 수 있음을 안내하면서 불필요한 우회를 줄임             |
| 응답 형식        | 기존 생성형 코스 객체 구조 유지                             | Result/Detail/CourseCard/MapView 재사용                                    |
| 코스 제목        | `출발-도착 랜덤 산책 코스`                                  | 순환 코스와 의미를 구분                                                    |
| 실패 대응        | ORS 실패 시 경유지를 바꿔 최대 3회 재시도                   | 사용자 한 번의 요청 안에서 성공 가능성을 높임                              |
| fallback         | DB 코스 fallback 없이 실패 메시지 반환                      | 저장 DB 코스는 출발-도착 목적지를 만족하지 못하므로 무리한 fallback을 피함 |
| 즐겨찾기         | 생성형 코스는 숨김 유지                                     | 복원 가능한 영속 ID가 없기 때문                                            |

## 6. 랜덤 경유지 설계

출발-도착 코스의 핵심은 ORS 최단 경로만 호출하지 않고, 두 지점 사이 주변에 경유지를 넣어 산책 느낌을 만드는 것이다.

1차 구현에서는 외부 POI API를 추가하지 않고 좌표 계산만 사용한다.

- 출발지와 목적지의 중간점을 구한다.
- 출발지-목적지 방향 벡터와 수직 방향 벡터를 계산한다.
- 거리 조건과 seed를 바탕으로 중간점 주변 좌우 방향에 경유지를 만든다.
- 1km는 1개, 3km는 2개, 5km는 3개 경유지를 기본값으로 사용한다.
- 출발지와 도착지 사이의 기본 보행 거리가 사용자가 선택한 거리보다 길 것으로 보이면 경유지를 최소화한다.
- ORS 요청이 실패하면 같은 조건에서 seed를 바꿔 경유지를 다시 만들고 최대 3회까지 재시도한다.
- 경유지는 ORS가 실제 도로망에 맞춰 보정하므로, 서버는 대략적인 산책 방향성을 제공한다.

주의할 점은 생성 좌표가 강, 산, 사유지, 큰 도로 등 보행 불가능 영역 근처가 될 수 있다는 점이다. ORS가 3회 모두 경로 계산에 실패하면 사용자에게 출발지/도착지 조정 또는 다시 생성을 안내한다. 이 한계는 후속 Step에서 POI 기반 경유지 또는 보행 가능 영역 필터링으로 개선할 수 있다.

## 7. 사용자 안내 문구

출발-도착 코스는 기존 순환 코스보다 거리 의미와 실패 상황을 사용자가 오해하기 쉽다. 따라서 UI와 응답 안내 문구는 아래 기준을 사용한다.

| 상황                              | 안내 문구                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 거리 선택 영역                    | 선택한 거리는 출발지부터 도착지까지의 전체 예상 거리입니다. 출발지와 도착지가 이미 멀 경우, 선택한 거리보다 길어질 수 있습니다. |
| 현재 위치 버튼                    | 현재 위치를 출발지로 사용                                                                                                       |
| 기본 거리가 선택 거리보다 긴 경우 | 출발지와 도착지 사이의 기본 거리가 선택한 거리보다 길어, 우회 경유지를 줄여 경로를 생성했습니다.                                |
| ORS 최종 실패                     | 이 조건으로는 보행 경로를 만들지 못했습니다. 출발지나 도착지를 조금 조정하거나 다시 생성해 주세요.                              |

## 8. API 초안

### `POST /api/routes/address-point-to-point`

```json
{
  "startAddress": "서울 성동구 왕십리로 63",
  "startLatitude": 37.5446,
  "startLongitude": 127.0374,
  "endAddress": "서울 성동구 ...",
  "endLatitude": 37.55,
  "endLongitude": 127.04,
  "distance": 3,
  "time": 30,
  "type": "walk",
  "seed": 42
}
```

### 성공 응답

```json
{
  "success": true,
  "data": {
    "id": "generated-ors-...",
    "title": "출발-도착 랜덤 산책 코스",
    "source": "ors",
    "routeMode": "pointToPoint",
    "geometry": {
      "type": "LineString",
      "coordinates": []
    }
  },
  "meta": {
    "usedFallback": false,
    "retryCount": 0,
    "notice": "출발지와 목적지 사이를 산책하듯 걸을 수 있는 경로를 생성했습니다."
  }
}
```

### 기본 거리가 선택 거리보다 긴 경우

```json
{
  "success": true,
  "meta": {
    "usedFallback": false,
    "retryCount": 1,
    "notice": "출발지와 도착지 사이의 기본 거리가 선택한 거리보다 길어, 우회 경유지를 줄여 경로를 생성했습니다."
  }
}
```

### 최종 실패 응답

```json
{
  "success": false,
  "message": "이 조건으로는 보행 경로를 만들지 못했습니다. 출발지나 도착지를 조금 조정하거나 다시 생성해 주세요."
}
```

## 10. 검증 항목

- 순환 코스 모드에서 기존 주소 기반 순환 코스 생성이 그대로 동작하는지 확인
- 출발-도착 코스 모드에서 출발지와 도착지를 모두 선택해야 버튼이 활성화되는지 확인
- 현재 위치 버튼이 출발지 입력 보조로만 제공되는지 확인
- 출발-도착 코스 생성 시 ORS 경로가 출발지에서 시작해 도착지에서 끝나는지 확인
- 출발지와 도착지 사이의 기본 거리가 선택 거리보다 긴 경우 우회 경유지를 줄이고 안내 문구가 표시되는지 확인
- 다시 추천 시 같은 출발/도착 조건에서 다른 경유지 seed로 경로가 바뀌는지 확인
- ORS 실패 시 서버가 최대 3회까지 경유지를 바꿔 재시도하는지 확인
- 3회 모두 실패하면 DB 코스 fallback 없이 실패 메시지를 반환하는지 확인
- 결과 카드 지도와 상세 지도에서 출발/도착 마커가 분리되어 보이는지 확인
- 생성형 출발-도착 코스에서 즐겨찾기 버튼이 노출되지 않는지 확인
- 공유 버튼이 기존 생성형 코스 정책대로 동작하는지 확인
- 모바일 375px 화면에서 주소 입력 영역이 과도하게 길어지거나 겹치지 않는지 확인
- `npm.cmd --prefix client run lint`
- `npm.cmd --prefix client run build`
- 수정한 서버 JS 파일에 대해 `node --check <file>`

## 11. 확정 구현 기준

Step 26 구현 기준은 아래와 같이 확정한다.

| 항목                   | 확정 기준                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 거리 조건 의미         | 사용자가 선택한 거리는 출발지부터 도착지까지의 전체 예상 거리로 처리한다.                                                     |
| 기본 거리가 더 긴 경우 | 출발지와 도착지 사이의 기본 보행 거리가 선택 거리보다 긴 경우, 랜덤 경유지를 최소화하고 안내 문구를 `meta.notice`에 포함한다. |
| 현재 위치 사용 범위    | 현재 위치 사용 버튼은 출발지에만 제공한다.                                                                                    |
| 도착지 입력            | 도착지는 주소 검색으로만 선택한다.                                                                                            |
| ORS 실패 fallback      | 저장 DB 코스 fallback은 사용하지 않는다.                                                                                      |
| 실패 재시도            | 서버 내부에서 랜덤 경유지를 바꿔 최대 3회까지 재시도한다.                                                                     |
| 최종 실패 응답         | 3회 모두 실패하면 다시 생성 또는 주소 재선택을 안내하는 실패 응답을 반환한다.                                                 |
| 경유지 랜덤 방식       | 1차 구현에서는 좌표 계산 기반으로 랜덤 경유지를 생성한다.                                                                     |
| 후속 개선              | POI 기반 경유지 선택, 우회 강도 조절, 상황 프리셋은 후속 Step에서 검토한다.                                                   |

## 12. 한계와 후속 검토

- 랜덤 경유지는 좌표 계산 기반이므로 실제 산책하기 좋은 장소를 보장하지 않는다.
- ORS가 보행 불가능 영역으로 판단하면 경로 생성이 실패할 수 있다.
- 생성형 코스 저장, 즐겨찾기, 딥링크 복원은 별도 저장 정책이 필요하다.
- 향후에는 카카오/OSM POI 기반 경유지 선택, 사용자가 원하는 우회 강도 조절, 점심 산책/퇴근 산책 같은 상황 프리셋을 검토할 수 있다.
