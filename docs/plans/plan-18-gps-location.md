> **관련 문서**: [step-18-gps-location.md](../steps/step-18-gps-location.md) | [pr-18-gps-location.md](../pr/pr-18-gps-location.md)

## 1. 작업 배경

RWR의 MVP는 PostgreSQL에 저장된 코스 중 사용자가 선택한 거리, 소요 시간, 운동 유형에 맞는 코스를 랜덤 추천하는 방식으로 구현되어 있다.

초기 GPS 계획은 Geolocation API로 현재 위치를 가져오고, Haversine 공식으로 기존 코스 시작점까지의 거리를 계산해 가까운 코스를 우선 추천하는 방향이었다.

하지만 최종 목표는 단순히 "이미 있는 코스 중 가까운 코스"를 보여주는 것이 아니라, 사용자의 현재 위치를 기준으로 매일 지루하지 않은 걷기/조깅/러닝 코스를 자동 추천하는 것이다.

따라서 Step 18에서는 기존 DB 코스의 가까운 순 정렬을 메인 기능으로 구현하지 않고, GPS 기반 자동 코스 추천 옵션과 기존 랜덤 추천 fallback 구조를 먼저 추가한다.

---

## 2. 목표

사용자가 추천 방식을 선택할 수 있게 하고, `GPS 자동 추천` 선택 시 현재 위치 권한을 요청한다.

Step 18에서는 실제 외부 라우팅 API 연동까지 진행하지 않는다. 위치 취득 성공/실패 여부와 관계없이 기존 PostgreSQL 랜덤 추천으로 fallback하며, 결과 화면에 fallback 이유를 안내한다.

---

## 3. 요구사항 요약

- 홈 화면에 `랜덤 코스` / `GPS 자동 추천` 추천 방식 선택 옵션을 추가한다.
- `GPS 자동 추천` 선택 후 추천 버튼 클릭 시 Geolocation API로 위치 권한을 요청한다.
- 위치 권한 허용, 거부, 실패 모두 기존 랜덤 추천으로 fallback한다.
- 위치 좌표는 서버로 전송하지 않는다.
- 기존 거리/시간/운동 유형 조건 필터는 유지한다.
- 컴포넌트에서 직접 `fetch`를 호출하지 않고 기존 `client/src/api/` 모듈을 유지한다.
- MVP 중심 문서에서 최종 목표와 달라진 내용은 삭제하지 않고 변경 사유를 남겨 보정한다.
- `npm.cmd run lint`, `npm.cmd run build`를 실행한다.

## 6. 구현 정책

### 6.1 추천 방식

| 추천 방식     | 설명                                                                |
| ------------- | ------------------------------------------------------------------- |
| 랜덤 코스     | 기존 PostgreSQL 코스 랜덤 추천                                      |
| GPS 자동 추천 | 현재 위치 권한 요청 후 Step 18에서는 기존 DB 랜덤 추천으로 fallback |

### 6.2 fallback 정책

아래 상황에서는 기존 DB 랜덤 추천으로 전환한다.

- 브라우저가 Geolocation API를 지원하지 않음
- 사용자가 위치 권한을 거부함
- 위치 취득 시간이 초과됨
- GPS 기반 추천 엔진이 아직 연결되지 않음
- 향후 외부 라우팅 API가 실패함

### 6.3 위치 정보 정책

- 위치 권한 요청은 사용자가 `GPS 자동 추천`을 선택했을 때만 수행한다.
- Step 18에서는 위치 정보를 서버로 보내지 않는다.
- Step 19에서 ORS를 붙일 경우, 사용자 위치가 ORS 외부 API로 전송된다는 점을 UI/문서에 명확히 안내한다.
