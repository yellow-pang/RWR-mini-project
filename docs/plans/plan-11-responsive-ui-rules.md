## 1. 작업 배경

`docs/images`의 모바일 목업을 참고해 UI를 정리하는 과정에서 실제 서비스 화면이 목업용 스마트폰 프레임처럼 보일 수 있는 요소가 있었다.

또한 `docs/private`의 코드 작성 규칙을 점검한 결과, 현재 프로젝트 기준은 정적 데이터나 localStorage 목록이 아니라 React + Express + PostgreSQL 풀스택 구조로 맞춰야 한다.

따라서 이번 작업은 디자인 방향을 유지하면서도 실제 웹/앱 반응형 화면에 맞게 UI를 보정하고, 기능이 없는 헤더 아이콘이 버튼처럼 오해되지 않도록 정리하는 것을 목표로 한다.

---

## 2. 작업 목표

- 목업용 스마트폰 상태바, 노치, 하단 홈 인디케이터 같은 장식 요소를 실제 웹/앱 화면에서 제거한다.
- 모바일에서는 앱처럼 전체 화면을 사용하고, PC에서는 중앙 웹앱 컨테이너로 표시한다.
- 요구사항을 우선해 조건 초기화와 추천 버튼 활성화 흐름을 유지한다.
- 메뉴, 알림, 필터, 삭제처럼 아직 구현되지 않은 기능은 실제 버튼으로 노출하지 않는다.
- 코스 지도 프리뷰는 특정 코스명으로 고정하지 않고 중립적으로 표시한다.
- CSS 색상과 그림자는 CSS Custom Properties 중심으로 관리한다.
- 풀스택/PostgreSQL 기준의 private 작업 규칙과 충돌하지 않도록 점검한다.

## 3. 수정 계획

| 순서 | 작업 | 내용 |
| --- | --- | --- |
| 1 | 기존 UI 구조 확인 | `Layout`, `TabBar`, 주요 페이지 헤더 구조 확인 |
| 2 | 반응형 레이아웃 보정 | 목업용 스마트폰 프레임 제거, 모바일/PC 레이아웃 재정의 |
| 3 | 요구사항 우선 점검 | 조건 초기화와 추천 버튼 비활성 조건 확인 |
| 4 | 헤더 아이콘 정리 | 기능 없는 버튼을 비상호작용 아이콘으로 전환 |
| 5 | 지도 프리뷰 정리 | `서울숲` 고정 라벨 제거 및 중립 프리뷰 유지 |
| 6 | CSS 규칙 정리 | 하드코딩 색상/그림자 값을 CSS 변수로 이동 |
| 7 | 검증 | lint/build 및 변경 파일 확인 |
| 8 | 문서화 | Plan/PR/Step 문서 작성 |

## 5. 검증 계획

| 검증 항목 | 방법 | 기대 결과 |
| --- | --- | --- |
| 정적 검사 | `npm.cmd run lint` | ESLint 오류 없음 |
| 빌드 | `npm.cmd run build` | Vite production build 성공 |
| 기능 없는 버튼 점검 | JSX에서 헤더 장식 아이콘 확인 | `button`이 아닌 정적 요소로 표시 |
| 요구사항 점검 | 홈 조건 초기화/버튼 비활성 상태 확인 | 전체 조건 선택 전 추천 비활성 |
| 변경 범위 확인 | `git status --short` | 의도한 클라이언트/UI 문서 변경만 존재 |
